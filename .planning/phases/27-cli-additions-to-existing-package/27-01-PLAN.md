  <action>
  Refactor the private `runSetupAwsEnvsNonInteractive` function in `src/commands/setup-aws-envs.ts`:

  1. **Change the signature** from `(configPath: string)` to accept a parsed config object:
     ```typescript
     export interface SetupAwsEnvsNonInteractiveConfig {
       email: string;
       projectDir?: string; // defaults to process.cwd()
     }
     ```
     The function was private and accepted a file path. Now it's exported and accepts an in-memory config object. The config validation (Zod) should happen inline — call `SetupAwsEnvsConfigSchema.safeParse(config)` and throw `Error` on failure (not `process.exit`).

  2. **Replace `requireProjectContext()` call** with `detectProjectContext()` (the non-exiting variant already exported from `src/utils/project-context.ts`). If context is null, throw an Error with the same message that `requireProjectContext` would print. This prevents `process.exit(1)` from killing the MCP server.

  3. **Replace ALL `process.exit()` calls** inside the function body:
     - `process.exit(0)` at line 593 → remove entirely (let the function return normally)
     - `handleAwsError(error)` calls → replace with `throw error` (or re-throw with the formatted message). The `handleAwsError` function itself can remain unchanged since the interactive path still uses it.
     - The catch block at lines 345-349 (root credential detection failure) → `throw error` instead of `handleAwsError(error)`
     - The catch block at lines 588-591 (main try/catch) → `throw error` instead of `handleAwsError(error)`

  4. **Remove the `loadSetupAwsEnvsConfig(configPath)` call** — the caller passes a parsed config object now, not a file path. Validate with Zod inline:
     ```typescript
     const parsed = SetupAwsEnvsConfigSchema.safeParse(config);
     if (!parsed.success) {
       throw new Error(`Invalid config: ${parsed.error.message}`);
     }
     ```

  5. **Keep the existing `runSetupAwsEnvs` interactive function unchanged.** It still calls the old code path via `--config` flag. Update the `--config` branch inside `runSetupAwsEnvs` to construct the config object and call the refactored `runSetupAwsEnvsNonInteractive`:
     ```typescript
     const awsConfig = loadSetupAwsEnvsConfig(configPath);
     await runSetupAwsEnvsNonInteractive({ email: awsConfig.email });
     ```
     (This preserves the existing CLI `--config` behavior.)

  6. **Export the function** by adding `export` keyword to the function declaration.

  7. **Export types** needed by MCP package: `SetupAwsEnvsNonInteractiveConfig`.

  8. **Update `src/index.ts`** to serve dual purposes — bin entry point AND named export surface:
     ```typescript
     #!/usr/bin/env node

     // Named exports for programmatic use (MCP package)
     export { runSetupAwsEnvsNonInteractive } from './commands/setup-aws-envs.js';
     export type { SetupAwsEnvsNonInteractiveConfig } from './commands/setup-aws-envs.js';

     // CLI entry point
     import { run } from './cli.js';
     run().catch((error) => {
       console.error(error);
       process.exit(1);
     });
     ```
     Note: The shebang + `run()` call means this file still works as a bin entry. The named exports are available when imported as a module. This is standard Node.js behavior — side effects only run when the file is the entry point, but the MCP package imports from `dist/index.js` where the `run()` call WILL execute.

     **IMPORTANT**: To prevent the CLI from auto-running when imported as a module, guard the `run()` call. Check if the current file is the entry point:
     ```typescript
     import { fileURLToPath } from 'node:url';
     const isMainModule = process.argv[1] === fileURLToPath(import.meta.url);
     if (isMainModule) {
       run().catch((error) => {
         console.error(error);
         process.exit(1);
       });
     }
     ```
     This ensures `import { runSetupAwsEnvsNonInteractive } from 'create-aws-project'` does NOT trigger the CLI.

  AVOID:

  - Do NOT change the signature of `runSetupAwsEnvs` (the interactive entry point)
  - Do NOT add MCP SDK dependencies to the CLI package
  - Do NOT use `.bind()` when saving/restoring function references (see STATE.md decision)
