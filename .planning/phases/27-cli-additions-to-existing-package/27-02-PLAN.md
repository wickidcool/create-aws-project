  Add `runInitializeGitHubNonInteractive` to `src/commands/initialize-github.ts`.

  1. **Define the config type** using Zod for validation:
     ```typescript
     export interface InitializeGitHubConfig {
       repoUrl: string;         // owner/repo, https://github.com/owner/repo, or git@github.com:owner/repo
       environments?: string[]; // defaults to all configured envs (dev, stage, prod)
     }
     ```
     Note: `GITHUB_TOKEN` comes from `process.env.GITHUB_TOKEN`, NOT from the config object. This follows CRED-01 (credentials from environment only).

  2. **Define the result type**:
     ```typescript
     export interface InitializeGitHubResult {
       results: Array<{
         environment: string;
         success: boolean;
         error?: string;
       }>;
       successCount: number;
       totalCount: number;
     }
     ```

  3. **Implement the function**:
     ```typescript
     export async function runInitializeGitHubNonInteractive(
       config: InitializeGitHubConfig
     ): Promise<InitializeGitHubResult>
     ```

     Implementation steps:
     a. **Validate config** with Zod `safeParse`. Throw on invalid. Schema: `repoUrl` required string, `environments` optional array of valid env names.
     b. **Read GITHUB_TOKEN from env**: `const token = process.env.GITHUB_TOKEN`. If missing/empty, throw:
        `throw new Error('GITHUB_TOKEN environment variable is not set. Set it in your .mcp.json env block: { "env": { "GITHUB_TOKEN": "ghp_..." } }')`
     c. **Detect project context**: Use `detectProjectContext()` (not `requireProjectContext`). If null, throw with "Not inside a project directory" message.
     d. **Parse repo URL**: Call `parseGitHubUrl(config.repoUrl)` — this already handles `owner/repo`, HTTPS, and SSH formats (confirmed in research).
     e. **Determine environments**: If `config.environments` provided, use those. Otherwise, use all environments that have `deploymentCredentials` in the config (same logic as `determineBatchEnvironments` with `--all`).
     f. **Create GitHub client**: `createGitHubClient(token)`
     g. **Process each environment in a loop with individual try/catch** for partial failure semantics:
        ```typescript
        const results: InitializeGitHubResult['results'] = [];
        for (const env of environments) {
          try {
            const creds = context.config.deploymentCredentials[env];
            if (!creds) {
              results.push({ environment: env, success: false, error: 'No deployment credentials found' });
              continue;
            }
            const githubEnvName = GITHUB_ENV_NAMES[env];
            await setEnvironmentCredentials(client, owner, repo, githubEnvName, creds.accessKeyId, creds.secretAccessKey);
            results.push({ environment: env, success: true });
          } catch (error) {
            results.push({ environment: env, success: false, error: error instanceof Error ? error.message : String(error) });
          }
        }
        ```
        This per-environment try/catch ensures one environment failing does NOT prevent the others from being configured. The caller gets a full report of what succeeded and what failed.
     h. **Return result** with per-env status, successCount, totalCount

  4. **Add exports to `src/index.ts`** (Plan 01 already set up the dual-purpose index.ts pattern):
     ```typescript
     export { runInitializeGitHubNonInteractive } from './commands/initialize-github.js';
     export type { InitializeGitHubConfig, InitializeGitHubResult } from './commands/initialize-github.js';
     ```

  AVOID:
  - Do NOT call `prompts()` anywhere in this function
  - Do NOT call `process.exit()` anywhere in this function
  - Do NOT accept the GitHub token as a parameter (CRED-01: env vars only)
  - Do NOT modify the existing `runInitializeGitHub` interactive function
